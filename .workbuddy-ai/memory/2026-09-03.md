# 2026-09-03

## Fix: budget department tidak berkurang saat permintaan suku cadang di-approve

**Keluhan:** `/permintaan-suku-cadang/update/1` sudah di-approve tapi "Terpakai" masih Rp 0.

**Akar masalah (2 bug terpisah):**
1. Record `permintaan_suku_cadang` id=1 punya `department_id = NULL` (dibuat sebelum migrasi
   `2026_09_03_110000_create_department_table.php` menambahkan kolom itu). Semua query
   `sum()->where('department_id', $id)` tidak pernah menghitung record ini.
2. Kolom `department.department_budget_terpakai` **tidak pernah ditulis di kode mana pun**
   (cuma di-seed 0 di DepartmentSeeder / DepartmentUserSeeder). Jadi tabel Department selalu
   menampilkan terpakai = 0 dan `getSisaAttribute()` selalu = full budget.

**Keputusan (dikonfirmasi user):**
- "Terpakai" dihitung mulai status **disetujui / sebagian / selesai**.
- Status **menunggu** = *reserve*, tidak mengurangi budget tapi tetap ikut dicek saat validasi
  create/update supaya tidak over-budget → ada accessor `tersedia = budget - terpakai - pending`.
- Record lama dengan `department_id` NULL di-backfill dari `department_id` milik user peminta.

**Perubahan:**
- `app/Models/PermintaanSukuCadang.php` — konstanta `STATUS_PEMAKAIAN` / `STATUS_RESERVE`,
  helper `terpakaiDepartment()` / `pendingDepartment()` / `sumByStatusDepartment()`,
  `resolveDepartmentId()`, dan `booted()`: `saving` (auto-isi department_id dari peminta),
  `created`/`updated`/`deleted` (sinkron budget, termasuk department lama kalau record dipindah).
- `app/Models/Department.php` — `syncTerpakai()`, `syncAllTerpakai()`, accessor `pending`, `tersedia`.
- `app/Http/Controllers/PermintaanSukuCadangController.php` — `budgetInfo()` terpusat;
  override `getDelete()` / `postDelete()` karena `DeleteAction` memakai mass-delete query builder
  yang **tidak memicu event model**.
- `app/Console/Commands/SyncDepartmentBudget.php` (baru) — `php artisan permintaan:sync-budget --backfill`.
- View: form permintaan (4 kartu: Department / Budget / Terpakai+Menunggu / Tersedia),
  dashboard KPI, tabel department (+ kolom Menunggu & Tersedia).

**Hasil setelah backfill:** IT budget 50jt, terpakai 1.500.000, tersedia 48.500.000.
Smoke test approve/reject/delete: create(menunggu) → pending +1jt, terpakai tetap;
approve → terpakai +1jt; reject/delete → balik lagi. Halaman update/1 HTTP 200.

**Catatan / belum dikerjakan:** kolom `department_periode` (bulanan/tahunan) belum dipakai
untuk memfilter periode — pemakaian budget saat ini diakumulasi selamanya. Perlu ditangani
terpisah kalau budget memang harus reset per bulan/tahun.
